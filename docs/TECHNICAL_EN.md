# cnc_app: technical documentation

Turns vector drawings (SVG) into GRBL 1.1 G-code (MKS DLC32), with a window (PySide6). It covers everyday shop work: outlines, drilling, pockets with islands, boards and their cutting order. Sending, homing, setting zero and previewing remain the job of UGS (Universal G-code Sender).

To use it, see the [README](../README.md), [QUICK_START_ES](../QUICK_START_ES.md) / [QUICK_START_EN](../QUICK_START_EN.md) and the user manual (`Manual_cnc_app_ES.pdf`, `Manual_cnc_app_EN.pdf`) in this folder. This document is in English; the Spanish version is [TECHNICAL_ES.md](TECHNICAL_ES.md).

The program's own text (window, messages, G-code comments) is available in Spanish and English. Names of menus, buttons and fields below are the ones of the **English interface**. The configuration files keep their Spanish keys (`recorrido`, `diametro`, `corte`...), which are quoted as they are.

## Quick start

```
pip install -r requirements.txt          # (TOML: Python 3.11+, or pip install tomli)
python -m pytest -q                       # all tests (the window tests need pytest-qt: requirements-dev.txt)

python cnc_gui.py                         # the window (or cnc_app.exe, see "Windows program")

# Verify any .nc independently of the generator
python verificar_nc.py output.nc --travel 651 1011 100

# Compare two .nc files (e.g. a reference one and ours): aligns them, measures differences and directions of rotation
python comparar_nc.py reference.nc output.nc --tool 4
```

The old command line (`svg_a_gcode.py`) has been moved to `tests/`: it is no longer part of the program and only the tests use it, to generate a `.nc` and compare it with reference G-code.

## The window

```
pip install -r requirements.txt           # includes PySide6
python cnc_gui.py [drawing.svg]           # or double-click cnc_gui.pyw (no console, on Windows)
```

1. **Open** an SVG (File → Open, or drag and drop it anywhere on the window; a `.cncjob` also works). On the left are the boards (tick the ones you want to generate) and below it the **color table**: one row for each combination of stroke and fill in the drawing.
2. On each row you choose what to do with that color: **Cut**, **Pocket**, **Drill** or **Ignore**, and if needed side, depth, pass, feeds and stepover (empty = the job's or the tool profile's, shown in gray). Through cuts also have a **Tabs** checkbox (see *Tabs*). Active rows are cut in table order (▲ ▼). If everything is ordinary through cuts, no recipe is needed and everything is cut together.
3. Set the **tool** (a profile from `herramientas.json` or a diameter in mm) and the **thickness**. Each board can have its own thickness, margin, rotation and **shift** (for two materials, or so that a piece that sticks out fits on the board); if the toolpath goes outside the board, the *Messages* tab says so and offers to apply the suggested shift.
4. **Drawing** shows the SVG with the dotted outline of the machine and the grid (see *Grid and machine travel*; ignored colors are dimmed; a click on a shape selects it and marks its row, see *Selecting shapes and groups*); **Machine** shows the toolpath already placed and rotated in machine coordinates, with the 651 x 1011 mm travel, the zero (red cross) and each operation in its color (hole, part, line, pocket, drill). *Rapids* draws the G0 moves.
5. **Generate G-code…** asks for the name and writes one `.nc` per ticked board (`NAME_board1.nc`...). If the file already exists, it asks before replacing it. If the job does not fit in the machine or breaks a limit, nothing is generated: the summary below the drawing says why. Alarms appear in red in the summary and in *Messages* but no longer have to be confirmed: the *checklist* is switched off for now (see *Limits and checklist*). The summary also gives the estimated machine time (see *Estimated machine time*).

**Menus**: *File* (open, save, profiles, machines, folders, generate), *Edit* (Undo, Redo, Select all, Select the current board, Clear selection and Delete selection), *Recipe* (open, save and reset the table), *Shapes* (groups, separate insides and outsides, sort rows), *Draw* (mouse tools, shapes, transformations, align, operations between shapes and tabs of the selection), *View* (views, grid, travel, wheel) and *Help* (language and about).

**A single window**: only one cnc_app window can be open per PC user (two could overwrite each other's tool and machine profiles or save the same job at once). If you open a `.cncjob` or an `.svg` with a double click (for example, with the `.cncjob` extension associated with the program) while the window is open, no second one appears: the new launch hands the file to the window that is already there and exits; the window comes to the front and opens it exactly as if you had dropped it onto it (if there are unsaved changes, it asks first). Opening the program again without a file just brings the window to the front. If a dialog is open at that moment (save, checklist, profiles...), the file waits until you close it, so the job is not changed from under you; if you pass another one in the meantime, the last one wins. If the open window does not respond (hung), the new launch opens its own as usual. The notification travels through a local Windows channel (a named pipe per user, `cnc_app-<user>`), without network or files; `--autotest` does not use it. To have two jobs open at once you need two Windows users, or `CNC_APP_INSTANCE=other-name` (for testing only).

**Small screens** (a 1366 x 768 laptop): at startup the window (1400 x 880 by default, or the size it remembered) is fitted to the free space on the screen and shown entirely. The divider between the drawing and the bottom panel (*Operations*, *Messages*, *Hold-down*) moves down smoothly with the mouse to a minimum of 90 px (the tabs and the first rows) and no panel disappears suddenly; whatever does not fit in a low panel is reached with its scroll bar. *Hold-down* enlarges the panel to 340 px while it is open, as long as 300 px are left for the drawing; if not, the panel keeps its height and scrolls. The left column has the width the job panel asks for (about 450 px); if it is narrowed further, a horizontal bar appears instead of cutting off the *Machines…* and *Profiles…* buttons.

The calculation is redone by itself whenever any value changes (in the background, without blocking the window). *File → Save job* saves settings, boards and table in a `.cncjob`, and inside it also carries the SVG exactly as it was when opened (key `svg_incrustado`, compressed): the job opens and its G-code can be redone on another PC without the SVG, even if that file has changed or no longer exists. Older `.cncjob` files do not carry it: opening them looks for the SVG by its path, next to the job, or asks where it is; *Recipe → Save recipe as…* writes the table as TOML and *Open recipe…* does the opposite. *F5* re-reads `herramientas.json` without closing the window. The initial values come from `cnc_app.toml` (including `receta = "..."`).

**Job and G-code folders** (*File → Job and G-code folders…*): two fixed folders, one for the jobs (`.cncjob`) and one for the G-code (`.nc`, including the hold-down marks G-code). You type the full path (`D:\Jobs`; pasting it with the quotes of "Copy as path" works) or look for it with *Browse…*; while you type, each path is checked and *OK* stays disabled if any is not valid. A path is valid if it is complete (starts with the drive or is a network path), exists, is a folder and can be written to (this is tested by creating and deleting a temporary file); empty means "not configured". With them set, *Open job*, *Save job* (if the job does not have a file yet; if it does, it is saved over it), *Generate G-code…* and *Generate marks…* start in the one that applies to them; the save dialog still lets you choose another without changing the fixed one. Without configuration everything works as before (the drawing's folder). **If a fixed folder stops being valid** (drive disconnected, folder deleted or renamed) the application does not silently replace it with another: it warns at startup in *Messages* and, when opening or saving, asks whether to configure it again, use the drawing's folder just this once, or cancel (which is the default). They are remembered **on each PC** (like the window position; in the Windows registry), so they do not travel with the program folder. The code is in `cnc/folders.py` (the rules, without Qt, with their tests), `cnc/gui/folder_actions.py` (remembering them and asking) and `cnc/gui/folders_dialog.py`.

**Tool profiles**: the *Profiles…* button next to the tool selector (or *File → Tool profiles…*, Ctrl+T) opens an editor with the list of profiles on the left and the form on the right: *New*, *Duplicate* (e.g. `em4` → `em4_mdf` for another material) and *Delete*. Each box is validated with the same rules as when the file is read; a profile that is not valid is marked with ⚠ and while there is any it cannot be saved. Below the profile it warns about what is missing (feed, plunge, flute length, pass), without preventing saving. *Save* rewrites `herramientas.json` and leaves the previous one as `herramientas.json.bak`; before opening, the editor re-reads the file (so it does not overwrite what you changed by hand) and if it is broken it does not open until you fix it. If you rename the profile that was selected, the window carries on with the new name; if you delete it, it warns. Ball and V tools are stored as data, but for now only the flat one (end mill) generates toolpaths.

**Selecting shapes and groups** (*Drawing* view): when the design does not tell the operations apart by color (all black, for example, but with pockets), you select shapes by hand and give them a row of their own in the table. *Click* on a line selects that vector (it gets a halo and its row is marked); *Ctrl+click* adds it or removes it; *Shift+click* adds it; *Shift+drag* draws a box and selects whatever fits entirely inside; a click on empty space clears the selection (so does *Esc*). The *Select* button above the table selects by **nesting level** (0 are the outsides, 1 what is inside another, 2 what is inside that...) and several levels can be ticked at once; *Open lines* selects the ones that do not close. *Move to group* (or *Ctrl+Shift+N*, "New group from the selection…") asks for a name and what it is (**Pocket**, **Cut**, **Drill** or **Ignore**) and creates a new row with those shapes (it is placed where it belongs by cutting order, see below); there you set its depth and feeds as on any other row. A group counts as one more color: in a pocket, the shapes of the group that lie inside another are islands that are not touched. The name is changed by double-clicking its cell; *Move to group → Remove from group* (*Ctrl+Shift+U*) sends the shapes back to their color, and a group left without shapes disappears. *Reset* leaves the groups as they are and puts all rows back to normal through cut.

The case that motivated it is a large drawing: 26 black vectors in four levels. Level 0 is the outer through cut, level 3 are through holes and levels 1 and 2 form a pocket: you select both levels in the menu, create the "Pocket" group of type *Pocket*, and level 2 remains as an island. The groups are saved in the `.cncjob` together with the number of shapes in the drawing; if the drawing has changed when it is opened, they are discarded with a warning in *Messages*. **Groups only exist in the window**: a recipe saved from the table carries its label colors, which are not in the SVG, so when it is opened on another drawing those operations find no shapes.

**Separate insides and outsides** (the *Separate inside/outside* button above the table, or *Shapes → Separate insides and outsides*, *Ctrl+Shift+I*): a **Cut** row with side "Auto" cuts correctly (holes first, then parts) but appears in the table as a single operation, so you cannot see which is which nor adjust each part separately. *Separate* splits it into one row per class of shape: **Insides** (side "Inside"), **Lines** (open shapes, "On the line") and **Outsides** ("Outside"), in that order and with the same settings (through, depth, pass, feeds) as the row it came from. The G-code produced is exactly the same; the difference is that now choosing a row marks its shapes in the drawing (each new row has its own color) and each one accepts its own depth, feed or pass without touching the other. If several rows can be separated, first choose the one you want in the table. Only Cut rows with side "Auto" that have at least two classes are separated; if the side is already fixed, or the row only has holes, parts or lines, the program says so and changes nothing. It can be undone (*Ctrl+Z*). A row that comes out of a group keeps its name ("Frame: insides", "Frame: outsides").

**Row order**: the table runs in the order of cutting, and the correct order is always **drills, pockets, insides, lines and outsides** (small things and what is inside first, and the part is released last). The program respects this on its own: when a drawing is opened, a group is created or the type or side of a row changes, the row is placed where it belongs. If it is moved by hand with the ▲▼ arrows and the order stops being correct, a **red warning** appears above the buttons with what is wrong ("“Pocket” (pockets) comes after “stroke #000000” (outsides)"), the **Sort** button (or *Shapes → Sort the rows…*) fixes it, and the warning continues as a red alarm in the summary and in *Messages* (before, with the checklist switched on, it had to be accepted when generating). A row set to "Auto" that mixes holes and parts cannot be sorted together with another that also mixes them: the warning asks for *Separate* first. With everything as normal through cuts there is no order to spoil (everything is cut together, holes before parts), so there is no warning. Another new alarm: an "Auto" cut row that, deciding only among its own shapes, would cut on the outside what in the whole drawing is a hole (for example, a row of holes that was left alone); the solution is *Separate* or fixing "Inside"/"Outside".

**Hold-down** (the *Hold-down* tab, next to *Operations* and *Messages*): helps to decide where to nail or screw down the sheet without hitting a cut or a part. When it is opened the window switches to the *Machine* view and paints in green the area where the sheet can be held, with the proposed points numbered. The calculation starts from the real toolpath: the corridor the tool leaves (with its radius and a margin to the cut), the edge of the sheet (with its margin) and which pieces come loose when cutting. **Bridges count as toolpath** (the tool passes over them raised, at half height: nothing is held there either) **and close the contour**: a part with bridges is still a part, not scrap. Ends of pieces that touch within 0.1 µm are taken as the same point: with several passes the calculation leaves differences of that size (depending on the processor), and a contour that looked open because of that left the part as scrap. **Parts are never held**, nor are the interior cut-outs that come loose (holes and closed lines); only the frame around the parts counts. The proposal puts one point on each large piece of scrap that comes loose, then just enough so that no place on the sheet is farther than the *reach* (300 mm by default) from a point, and if on a large sheet (more than 4 times the reach squared: 600 × 600 mm with 300) fewer than the *minimum points* (6) come out, it adds the missing ones; finally it spreads them so that they end up at similar distances from each other. **It keeps away from corners**: it proposes nothing closer than the *distance to corners* (100 mm) to a corner of the sheet, because on the machine bed they would always land in the same spot and it would end up battered. **Never so close to the cuts**: it puts them at the *distance to the cuts* (20 mm from the cutting edge) or more, because a small error when nailing must not hit the cut (the *margin to the cut* below is the absolute minimum; this one is the comfortable distance). And it **does not put two points together** closer than the *minimum spacing* (200 mm): a rigid sheet does not need clamps so close together. On a large sheet, with the *In rows and columns* box ticked, the points go **on a regular grid** (on a 610 × 1015 mm sheet, two columns by four rows), with the bottom row **near the bottom edge** (*Bottom row at* 40 mm from the edge, without reaching the corner); each point goes to its place in the grid or, if there is a part or a cut there, to the nearest comfortable spot. If the grid does not fit (the cell does not fit within the reach, or it asks for quite a few more points than the free distribution) or the sheet is small, they are distributed freely: at similar distances from each other. These rules only give way if there is no other way to cover the sheet or to hold a loose piece, and in this order: first the spacing (gradually, not all at once), then the corners and, last, the clearance to the cut; a point that ends up closer to the cut than comfortable is shown with a ⚠ in the table and in the warning above (also if you place it by hand). On a small sheet a minimum of 3 points is proposed, if they fit. The numbers are in the *Point proposal* box (empty = the usual) and travel with the saved job; they only apply to the proposal, by hand a point can be placed anywhere inside the green area. The points are numbered **from far to near**, like the cutting order: by rows, from the one with the largest Y (the back of the machine bed) to the one with the smallest Y, and within each row from left to right (two points are in the same row if their Y is similar, up to 30 mm from one to the next). You choose between *nail-gun nail* (margin to the cut 6 mm, to the edge 12) and *lag screw* (10 and 15); the margins can be changed by hand (empty = the type's).

The points can be touched up: a click on the canvas adds one (if it cannot go there, the status bar says why), a click on a point removes it, and the coordinates in the table can be typed (with comma or point). A point typed in an unsafe place is accepted but shown in red with the reason, and when generating the marks it asks first. *Propose again* discards what was edited on that board. Each board has its own points (a drawing without a frame has its own for the whole drawing, on the assumed sheet: if your real sheet is larger, raise *Zero at (mm) from drawing* so that the assumed one grows equally on all four sides); they are saved with the job (`.cncjob`) together with the type, the reach and the margins, and if you change the tool or anything that moves the toolpath they are checked again against the new one.

*Generate marks…* writes `NAME_board1_marks.nc` (or `NAME_marks.nc` if the drawing has a single board): a short G-code that, **with the spindle stopped**, takes the machine to each point, rises to the *mark height* and makes an `M0` pause; at each pause the point is marked under the tip and *Resume* is pressed in UGS. The points are visited **from far to near** (largest Y first, each row from left to right) even if you added or moved them by hand; if the order in the table is different, the comment of each point in the program says which one it is in the window (`(Point 1 of 6 - it is number 4 in the window)`). When it finishes it does the same as the job (Home or return to origin, if ticked). Afterwards the sheet is removed and nailed or screwed down at the marks.

**Drawing and editing (the *Draw* menu)**: lets you add or touch up pieces without going back to the vector drawing application. It works with measurement dialogs (in mm, with comma or decimal point; *OK* stays disabled while any value is missing) and on whatever you have selected in the *Drawing* view. *New empty drawing* (Ctrl+N) starts from scratch: the 240 × 160 mm page is shown dashed and the zero with a red cross.

- **Draw shape**: rectangle (with rounded corners), circle, ellipse (with rotation), regular polygon (the size is given as a radius or as the distance across flats, the one of a hexagonal nut's wrench), slot (rectangle with rounded ends between two centers) and line or polyline (one point per line, "X Y" or "X; Y"; with *Close* it is an outline). Curves are drawn with straight segments that never deviate more than 0.005 mm from the true curve. The stroke color is chosen among those in the drawing or with *Other color…*, and it cannot be the label color of a group.
- **Move, Place at, Rotate, Resize, Mirror**: *Move* is relative; *Place at* puts the lower-left corner of the selection at a point; *Rotate* rotates around the center of the selection (or the point you type; positive is counterclockwise); *Resize* asks for the final size, with a box to keep proportions and from the center or from the corner; *Mirror* flips the selection about a vertical or horizontal axis (by default the one through its center).
- **Copy as array** (columns × rows with the spacing between equivalent points) and **Copy around a circle** (n shapes distributed around a center; with 360° they are spread over the full turn, with less the last one ends up at that angle). The copies keep the group of the shape they come from.
- **Offset** outwards or inwards, with rounded or sharp corners, keeping the originals or not; an open line comes out surrounded. **Union of shapes**, **Subtract shapes** (from the first or from the last, which are the oldest or the newest in the drawing), **Intersection of shapes** and **Close outline**. What comes out is always a polygon without holes or a line: a hole left by a subtraction or an offset comes out as a separate shape inside the other, which is how the program understands parts and holes (by nesting). These operations only work with closed shapes (open lines are closed first).
- **Edit menu**: **Undo** (Ctrl+Z) and **Redo** (Ctrl+Y) go back up to 200 steps and also undo group changes (the menu says what will be undone); **Select all** (Ctrl+A: only the parts and holes, never the frame of a board); **Select the current board (with its frame)**, which selects a whole board together with its rectangle (so it can be moved or copied entire); **Clear selection** (Esc) and **Delete selection** (Delete).

Things worth knowing: measurements are those of the drawing (X to the right, Y upwards, zero at the lower-left corner of the page). **A rectangle with shapes inside is taken as a board** (the material: it is not cut and the zero goes to its corner); if you draw a piece that is a rectangle with something inside, untick *Detect boards*; the window warns when a new shape becomes a board and, if it is the first in the drawing and is not already at 0,0, it asks **Move it to 0,0?**: if you say yes, the board and the whole drawing move until its lower-left corner is at X 0, Y 0 (a single Undo step); if not, it stays where you drew it. A new shape **outside every board is not cut** (it also warns). Boards keep their thickness, margin and hold-down points when you move or copy shapes, and the hold-down points follow the board if you move it. If there are unsaved drawing changes, the window asks before opening something else or closing.

The edits are saved in the `.cncjob` (the `edicion` section: the list of operations, which are redone on top of the SVG when it is opened; if the SVG has a different number of shapes they are discarded with a warning in *Messages*, just like the groups). A new drawing has no SVG: everything is in the `.cncjob`, and when it is saved for the first time it takes the name of the job (the `.nc` files come out with it). The undo history is **not** saved: when the job is opened again, what came before can no longer be undone. The code is in `cnc/drawing_edit.py` (pure functions, with their tests) and `Project.edit`.

**Drawing and moving with the mouse** (*Drawing* view): above the canvas there is a strip with the tools *Select*, *Rectangle*, *Circle*, *Ellipse*, *Polygon*, *Slot*, *Line* and *Move*. They are also in *Draw → Draw with the mouse* and are chosen with a key: **V** select, **R** rectangle, **C** circle, **E** ellipse, **P** polygon, **S** slot, **L** line, **M** move (the status bar says what to do at each moment).

- **Drawing**: *click* on the first point and *click* on the second, or *drag* from one to the other (when you release, the second is set). While you move the mouse the shape is shown dashed and, next to the cursor, a label with live measurements: "50 × 30 mm", "Ø 20 mm · radius 10", "6 sides · radius 10 mm · across flats 17.32 mm · rotation 90°", "total length … mm", "ΔX … · ΔY … mm". The rectangle and the ellipse are given by two corners of their box; the circle and the polygon, by the center and a point on the edge (or a vertex, which also fixes the rotation); the slot, by the centers of its two ends. The **line** goes point by point: *double click*, *Enter* or *right click* finish it, a *click on the first point* (with three or more) closes the outline, and *Backspace* removes the last point. Shapes take the stroke color from the mouse options.
- **Move**: first select what you want to move (with *Select*), switch to *Move*, click on a starting point (for example a corner of the selection) and on an end point; with **several shapes** selected they act as one: their circumscribed rectangle is shown (dashed, with the four corners marked), the measurement strip and *Place at…* refer to it, and they are grabbed by its corners, side midpoints or center, not by the points of each shape; the label gives the displacement and a "ghost" of the selection is shown at its new place. The selection is not attracted to itself. If you change the selection halfway, the move is cancelled.
- **Snap**: the cursor sticks to the points of the shapes that already exist, within about 10 screen pixels (not mm: the more you zoom in, the more precise it is). What it snapped to is shown with a green marker (square: corner or start; circle: center, box or zero; diamond: midpoint or quadrant) and the label says so. The point nearest the cursor wins; if two are at the same distance (two shapes touching at the same point, for example), the one that matters most: corner or start, quadrant, center, midpoint, box points and, finally, the drawing's zero. On a shape with more than 400 corners (a very fine path) only the corners are offered, not the midpoints. When moving, the corners, the center and the midpoints of the box of the selection are also offered. With the line, the start point already placed attracts in order to close (the marker turns amber). An impossible shape (two equal points, for example) is rejected with a notice in the bar and nothing changes.
- **Shift and Ctrl**: *Shift* restricts: square in the rectangle, circle in the ellipse; in the line, the slot and the move, angles in 45° steps; in the polygon, the rotation in 15° steps. *Ctrl* turns the snap off while you hold it (what remains is the grid, if there is one, or the point with two decimals).
- **Esc**: cancels what you are doing (the points placed); a second time, it leaves the tool (back to *Select*), and a third clears the selection, as always. *Right click* does the same (on a line with two or more points, it finishes it).
- **Panning** without leaving the tool: *middle button* or *space bar + drag*. In *Select* you keep dragging with the left button as before. The wheel zooms (turning it forwards zooms out and backwards zooms in; *View → Reverse mouse wheel* changes the direction and is remembered on each PC; a side wheel does nothing) and a double click fits the view, except with a drawing tool selected (with a line half drawn, the double click finishes it). When going from the *Drawing* view to *Machine* (or back, or to the *Hold-down* tab, which opens *Machine*) the zoom and the area being viewed are kept, also with the job rotated; if that area is not in the other view (another board), everything is shown.
- **Mouse options** (*Draw → Draw with the mouse → Mouse options…*): corner radius of the rectangle, sides of the polygon, width of the slot, grid step (0 = no grid; free points are rounded to it and the view's grid uses that step), snap on or off and stroke color. What cannot be given with the mouse (the radius, the sides, the width) comes from here. They are **not saved** when the program is closed: they go back to the factory values (square corners, 6 sides, 8 mm slot, no grid, snap on).
- Each shape or move made with the mouse is **one more operation in the history**: it is undone with Ctrl+Z, saved in the `.cncjob` and counts just as if it had come from a dialog. The view does not jump when drawing. Rotating and resizing are still done through dialogs. The code is in `cnc/draw_tools.py` (snap and measurements, without Qt, with their tests) and `cnc/gui/draw_layer.py` (the mouse on the canvas).

**Measurements of the selection** (*Drawing* view): below the mouse tools there is a strip with the numbers of the selected shape, which can be read and **typed**: *X*, *Y*, *Width* and *Height* (and *Diameter* and *Radius* if it is a circle). *X* and *Y* are those of a **point on the box surrounding the shape** (the circumscribed rectangle, whatever the shape), and that point is chosen in the **nine-point selector** on the left of the strip: the four corners, the middle of each side and the center. At first it is the lower-left corner (the center, for a circle); as soon as you choose another point, it applies to everything you select afterwards (to put the bottom of a circle at Y 0, or its side against a wall at X 0, choose the bottom point or the middle of a side and type the number). It is chosen with the mouse or with the keyboard arrows if the selector has focus, and the tooltips of the boxes say which point they are talking about. With several shapes selected it is the box of all of them together ("2 shapes"). Type the number (comma or point) and press *Enter* or move to another box: it is one more operation in the history ("Change measurements"), it is undone with Ctrl+Z and saved in the `.cncjob`. **The chosen point does not move when the size changes**: with the upper-right corner chosen, a new width grows to the left; with the center, to both sides (a circle changes diameter around its center and remains a circle: it is rebuilt with as many points as it needs, not enlarged crudely). What you do not touch is not rounded: changing only the Y does not distort anything. A rectangle with rounded corners **keeps** them (if the new size leaves no room for them, the radius is reduced and a notice appears); an ellipse with straight axes is rebuilt exactly, and the other shapes are stretched as they are. A straight line does not accept a measurement on the axis along which it has no size. A width or a height of zero, an empty box or a measurement that changes nothing do nothing: the box returns to the real value and the status bar says why. If nothing is selected the strip is switched off and says so; in the *Machine* view as well. The logic (reading the box and the points and setting them) is in `cnc/drawing_edit.py` (`measures_of`, `Measures.point`, `box_corner`, operation `medidas`, without Qt, with their tests in `tests/test_measures.py` and `tests/test_align.py`), the strip in `cnc/gui/props_bar.py` and the selector in `cnc/gui/anchor_picker.py`. *Place at…* and *Resize…* in the *Draw* menu are still there (the latter with proportions and from the center).

**Align** (with two or more shapes selected): to the right of the measurement strip there are six buttons with icons, the same as in the *Draw → Align* menu: *Align left*, *Center horizontally*, *Align right*, *Align top*, *Center vertically* and *Align bottom*. **Each whole shape** is aligned (by its circumscribed box: the bottom of a circle, the face of a rectangle…) with the box of **all the selected shapes together**: with *Align left* all the left faces move to the X of the one farthest left, with *Align bottom* all the bottom faces to the Y of the one lowest, and with *center* all the centers to the center of the common box. Shapes that are already in place (within a micron) are not touched; if all are, nothing changes and the status bar says so. It is a single history operation with the name of what was done ("Align bottom", "Center vertically"…): it is undone with Ctrl+Z and saved in the `.cncjob`. The buttons are disabled unless at least two shapes are selected. If a piece is going to end up aligned with the board, select both (the board stays still as long as it is the one that sticks out on that side) and check that the direction is the one you want; to place a shape at an exact measurement use the measurement strip. The logic is the `alinear` operation of `cnc/drawing_edit.py` (`align_edit`, with its tests in `tests/test_align.py`) and the icons are drawn in `cnc/gui/align_icons.py`.

**Grid and machine travel** (*Drawing* and *Machine* views): two buttons above the canvas, also in the *View* menu, which are remembered on each PC and come switched on from the factory.

- **Grid**: thin lines and, every so many of them, a stronger one with its measurement in mm on the edge of the canvas (X at the bottom, Y on the left); at the top right it states the step ("grid 50 mm"). Without a mouse grid, the step adapts to the zoom by itself (from the series 1, 2, 5, 10, 20, 50… mm, never with the lines closer than 14 pixels). With a grid step set in *Mouse options*, the grid is that one (or a multiple of it if it does not fit with so much zoom out) and falls exactly where the free points fall. The measurements are those of the drawing (in the *Machine* view, those of the machine, with the zero at the red cross).
- **Travel** (*Drawing* view only): the rectangle of **blue dots** of what the chosen machine reaches (X × Y travel of its profile), placed on the **board being viewed**, with the same rotation and the same zero that the G-code will have: the red cross is the machine zero (X0 Y0) and the legend at the top says which machine it is. This shows at a glance whether the board fits and on which side it goes over. It appears as soon as a machine is chosen, even if there is no tool or thickness yet. If the rotation is automatic and the board only fits rotated, the rectangle appears rotated. It does not count for *Fit* (with a machine much larger than the piece, the fit still frames the piece). In the *Machine* view, the travel was already drawn as a rectangle; now it is the same blue dots. The calculation is in `lay_out` and `machine_frame` (`cnc/pipeline.py`, the same one the G-code uses), `Project.machine_frame` and `cnc/grid.py` (the grid, without Qt, with their tests).

Not available yet: importing DXF, settings for an individual shape (only by color or by group), generating with a V tool, and warnings for small pieces (double-sided tape).

### Windows program (without installing Python)

`build_windows_onefile.bat` (with Python 3.11+ installed) generates `dist_onefile\cnc_app.exe` with PyInstaller: a **single self-contained file**, which is copied to another PC as it is (it is unpacked into `%TEMP%` on each launch). `herramientas.json`, `maquinas.json`, `cnc_app.toml` and the recipes go **next to the .exe** (not inside it) so they can be edited (**without `maquinas.json` next to the .exe nothing is generated**: the program does not assume a machine). Since PyInstaller rebuilds `dist_onefile` when compiling, the .bat first brings back into the program folder whatever you have edited there (e.g. the profiles with the tool or machine editor) if it is newer than the copy in the main folder, and then copies the four files next to the exe; this way a recompilation does not overwrite your profiles. It refuses to compile with `cnc_app.exe` open and when it finishes it waits for a key, whether it went well or badly, so you can read the result. Check without a window: `cnc_app.exe --autotest drawing.svg result.txt` writes in `result.txt` where it looked for the files, which profiles it read and whether it was able to calculate a job (with the first tool profile and the first machine profile if there are several, and it says so in the result). The exe carries its version (the one in `cnc/__init__.py`, which `cnc_gui.spec` reads when compiling) in the Windows version resource: right click on `cnc_app.exe` → *Properties* → *Details* (file and product version, e.g. 0.29.2). The folder build (`dist\cnc_app`) was abandoned in 0.29.1: the single file opens just as fast and is easier to carry around. On Linux, `bash build_linux.sh` does the same (`dist_linux/cnc_app`, a single file; it needs Python 3.11+ with `venv`): it creates `.venv-linux`, installs the dependencies, builds with `cnc_gui.spec` and checks the binary without a window with `--autotest`; with `--tests` it runs the tests first. PyInstaller cannot build for one system from another, so the Linux binary is built on Linux: it uses the system glibc, so it works on that Ubuntu/Mint version or a later one (the release one is built on Ubuntu 24.04). On macOS, `bash build_macos.sh` does the same for the Mac it is run on (run it once on each kind: Intel and Apple Silicon) and leaves `dist_macos/<intel|apple-silicon>/cnc_app_<version>_macos_<intel|apple-silicon>.zip` with `cnc_app.app` (a PyInstaller folder inside an `.app` bundle: a single windowed file is not recommended on macOS). It installs nothing on the Mac: uv, Python 3.12, the dependencies and the caches live in `.macos-build/<architecture>`; it only needs Apple's Command Line Tools, because PyInstaller calls `lipo` and `install_name_tool` on macOS (`xcode-select --install`, or a copy of that folder named `CommandLineTools` next to the program folder, which the script uses if they are missing). Recent PySide6 requires macOS 13 or 14: uv picks the latest one compatible with the Mac doing the build (on Monterey, 6.9). On macOS `app_dir()` is the folder that contains the `.app`, so `herramientas.json`, `maquinas.json` and `cnc_app.toml` go next to the `.app`. The program has an ad hoc signature, without an Apple certificate: the package includes `PRIMERA_VEZ_macOS.txt` explaining how to remove the download flag (`xattr -dr com.apple.quarantine`). If macOS does not let the application read the folder it sits in (removable-volume permission, e.g.), the file that cannot be read shows up as a startup warning instead of an error.

## Limits and checklist

> **Since v0.23 the checklist is switched off**: it turned out to be excessive for daily use. *Generate G-code…* writes without opening it. The limits below still block, and the alarms still appear in red (summary and *Messages*), they just no longer have to be confirmed. The switch is `ENABLED` in `cnc/checklist.py`; the idea is that later it will be switched on and off with an external file, so that it is not easy to change by accident. What follows describes how it works when switched on.

Ruining material and tools is expensive; studying a piece badly is not. That is why there are some **limits** that apply equally to everybody (experts or not): they are not skipped, the data is corrected. The numbers are all in `cnc/safety.py`, in a single place:

| Limit | Bound | What happens when exceeded |
|---|---|---|
| Spoilboard margin | 0.5 mm at most (0.2 is enough with a freshly surfaced spoilboard; 0.4 ensures the cut even if there are imperfections underneath) | The job is not calculated; the message states the limit |
| Material thickness | From 22 to 30 mm is an **alarm** (it is generated, but must be confirmed); above 30 mm it is not generated ("Is it a typing mistake?") | Block / alarm |
| Pass | 2 × the tool diameter at most (8 mm with the 4 mm tool; 6.35 mm with the 3.175). The real pass counts: the total depth divided into equal passes. With no pass in the profile, settings or table, the whole depth is a single pass | The job is not calculated; the message names the operation and says where to set a smaller pass |
| Fits in the machine | The toolpath has to fit within the travel of the job's machine profile (651 × 1011 mm on the shop's; see *Machines*) | The toolpath is shown, but the G-code is **not written** (before, it only asked) |
| Verification | After generating, the independent verifier (`cnc/verify_nc.py`, the same one as `verificar_nc.py`) checks the program: cuts above the surface, no feed, spindle off, lines longer than 79 characters... | If it finds anything, nothing is written |

The program cannot know whether a pass of 8 mm at 1200 mm/min is too much for a hard material such as MDF; that judgment is left to the tool profiles per material (`em4_mdf`...), but the program does prevent what makes no sense with any of them.

**Alarms**: things the program generates but that must be looked at before running, and that appear in red in the list: thickness over 22 mm, pieces closer to each other than the tool diameter, areas the tool does not reach (narrower than it or with very sharp corners) and a toolpath that goes outside the board (part of a piece lies outside the material; the *Apply suggested shift* button brings it inside). The summary below the drawing counts how many there are.

**Where each space alarm is**: the two space alarms (pieces closer to each other than the tool, and areas the tool does not reach) say where they are. In the text of the warning, as `Where: X.. Y..` (the same X and Y as the G-code; up to three places per warning and "and N more"). And in the **machine view**, with a red circle of the same size at any zoom on each place and the place when the mouse passes over it; between pieces, also the line between the two closest points. The legend under the drawing explains it. The circles are only a sign: they cannot be clicked, they do not move the view and they do not appear in the drawing view. For an area the tool does not reach, the place is the centre of each thick part (over 2 mm) left uncut; between two pieces, the midpoint of where the gap is smallest. If there are **more than 20 places** (`MAX_MARKS` in `cnc/generate.py`) none is marked and the list of warnings is not filled: **a single red warning** appears ("TOO MANY PROBLEM AREAS…") saying how many there are, and when *Generate G-code…* is pressed the program asks "Generate anyway?" (No by default), even if the checklist is switched off. None of this changes the G-code.

**Checklist** (the *Checklist before generating* window): it always opens when *Generate G-code…* is pressed, the same for everybody, like pilots' checklists: you are not asked to know, you are asked to look. At the top go the data the program calculates, one per job (the machine and its travel, tool and diameter, thickness + margin = depth, passes, feeds, cuts, size of the toolpath against the travel, the estimated machine time, rotation, where the zero ends up, safe Z, whether the spindle starts, what it does at the end). Below, one checkbox for each thing that **only whoever is in the shop can know**: the machine connected to UGS is the one in the profile (the first, so that the program of another is not taken to the shop); the mounted tool is the one stated and is tight; the material measures what is indicated; the zero X0 Y0 is where it says and Z0 on the top face; the material is held down and nothing sticks out or lies in the toolpath; the spindle is stopped (or is started by hand) and the speed controller is set. Each alarm of the job is another checkbox, in red. *Generate* is not enabled until **all** are ticked, there is deliberately no "tick all", and the default button is *Cancel* (a stray Enter cancels, it does not generate). The code is in `cnc/safety.py` and `cnc/checklist.py` (the rules and the content, without Qt, with their tests) and `cnc/gui/checklist_dialog.py` (the window).

## Estimated machine time (v0.23)

Each board carries its estimate of how long **the machine** will take: cuts, plunges, retracts, rapids and the `G4` dwells. It does not count marking, screwing down or cleaning, and `M0` pauses do not add up (there the person is in charge; the estimate says how many there are). It appears in the summary below the drawing (`≈ 1 h 35 min of machine time`, with the breakdown in the tooltip) and in the checklist (with the total when there are several boards). It is only informative: it blocks nothing and warns of nothing.

The calculation (`cnc/timing.py`, without Qt) imitates the GRBL 1.1 planner: each move goes at its feed, limited by the maximum feed of each axis (`$110`–`$112`); each axis accelerates at most as much as the profile says (`$120`–`$122`); and at each junction between two consecutive moves it does not brake completely, it passes at the speed allowed by the junction deviation (`$11`, 0.010 mm by default): a smooth curve hardly brakes, a sharp corner almost stops and a reversal stops completely. `M3`, `M5`, `G4` and `M0` synchronize (the machine stops before continuing). Without accelerations in the profile, the time can only be given at constant speed, which falls short, and the estimate says so. With jobs of hundreds of thousands of lines it takes a couple of seconds, so it is calculated in the plan thread and not when painting.

Checked against a real cut: a large drawing (256,853 lines, half of the moves shorter than 0.1 mm) in the UGS emulator, which carries the same `$11`, `$110`–`$112` and `$120`–`$122` as the shop's machine: estimated **1 h 35 min 00 s**, UGS **1:35:02**. Without accelerations in the profile only the time at constant speed is given (with the large drawing, 93.7 min: it falls short), and UGS's feed percentages are not taken into account if they are touched by hand.

## Machines: `maquinas.json`

Each job carries **its machine**: a profile with the travel (X, Y, Z) and what is known about the controller. The normal case is one machine per PC, but the PC that generates the G-code does not have to be the one that drives the machine (in a shop it is usually a dedicated PC with only UGS, to which the `.nc` arrives on a USB stick), so the profile travels with the job and is not deduced from the PC. The limits that used to be fixed at 651 × 1011 mm now come from the profile.

**How a profile is created**: by pasting what UGS shows when connecting (the console with `$$`, `$I` and the GRBL startup banner) or by typing the values by hand. In the window, *Machines…* (button next to the machine selector or *File → Machines…*, Ctrl+M) opens the editor; *New from a log…* asks for the log, shows **what it understood** (travel, feeds, accelerations, limits, Home, spindle, laser mode, firmware), what it **could not read** and, if the profile already exists, **what it would change**; it can only be accepted if the log contains the travel (`$130`, `$131` and `$132`). *Update this profile from a log…* changes only what the log brings and leaves the rest as it was (notes, origin). *New*, *Duplicate* and *Delete* work as in the tool editor; *Save* rewrites `maquinas.json` and leaves the previous one as `maquinas.json.bak`. Each box is validated with the file's rules and while anything is wrong it is not saved.

```json
{
  "maquinas": {
    "real": {"nombre": "Shop", "recorrido": [651, 1011, 100],
             "avance_max": 3600, "avance_max_z": 3600, "aceleracion": [200, 200, 100],
             "limites_blandos": true, "limites_duros": true, "homing": true,
             "husillo_max": 10000, "laser": false, "firmware": "Grbl 1.1",
             "origen": "$$ of the real machine (UGS, COM5)", "notas": "..."}
  }
}
```

Only `recorrido` is required; **what is missing is "unknown" and is not checked** (a value is never assumed). The file is validated as strictly as `herramientas.json`: a misspelled field (with a "Did you mean…?"), a repeated identifier or an absurd number gives an error that names the profile and the field, and while the file is broken nothing is generated.

| Rule | What happens |
|---|---|
| The toolpath fits in X and Y | The toolpath is shown, but the G-code is not written |
| Depth + safe Z fit in the Z travel | Not written: "It does not fit in Z…" with the measurements |
| *Home ($H) at the end* with a machine that has no Home (`homing: false`, like the emulator) | Not written |
| Starting the spindle (M3) with a machine in laser mode (`$32=1`) | Not written |
| Feed higher than the profile's (`avance_max`, `avance_max_z`) | Warning (does not block) |

**In each job**: the window has a *Machine* selector in the job panel; it is remembered per PC. The `.cncjob` stores the identifier and a **copy of the profile as it was when saved**: when it is opened, if the profile has changed it warns in *Messages*, and if it no longer exists the stored copy is used (it also warns). With more than one machine and none chosen, nothing is generated until one is chosen. The G-code carries on its second line `(Machine: name | travel X x Y x Z mm)` and **the first checkbox of the checklist is the machine** ("The machine connected to UGS is “Shop”…: this G-code is for it"): it is the defense against taking the program of another machine to the shop.

Profiles are created and edited in the window (*Machines…*, which also imports a UGS log saved in a text file: it shows what it understood and, if the profile already exists, it only changes what the log brings and leaves a `.bak` copy). `verificar_nc.py` accepts `--machine` and `--machines-file` (and then the travel and the feed come from the profile, not from `--travel` or `--max-feed`):

```
python verificar_nc.py output.nc --machine real
```

Without `maquinas.json` the window starts anyway, warns in *Messages* and **does not generate** until there is a machine: the library (`import cnc`) still uses the real machine by default, but the actual program does not assume one. The file that is delivered carries a single profile, `emulador` (an ESP32 with GRBL 1.1 firmware); each shop's machines are added with *Machines…*. The code is in `cnc/machines.py` (file, log reading and rules, without Qt, with their tests), `cnc/machinebook.py` (editing the list: new, duplicate, import, update) and `cnc/gui/machines_dialog.py` (the window).

## Tools: `herramientas.json`

One profile per tool, editable by hand (UTF-8). Only `diametro` is required; whatever is missing is entered in the job (feeds and pass).

```json
{
  "herramientas": {
    "em4": {"nombre": "End mill 4 mm", "tipo": "endmill", "diametro": 4,
            "flautas": 2, "longitud_util": 12, "rpm": 18000,
            "profundidad_pasada": 3.2, "feed": 300, "entrada": 200, "stepover": 40,
            "notas": "..."}
  }
}
```

| field | meaning |
|---|---|
| `nombre`, `notas` | free text (the name appears in the G-code header) |
| `tipo` | `endmill` (default), `ball` or `v` |
| `diametro` | mm (for a V, the maximum cutting diameter) |
| `flautas`, `longitud_util` | number of flutes; mm of useful flute (the program refuses to cut deeper than the flute) |
| `angulo` | included angle of the V in degrees; required for `v` and forbidden for the others |
| `rpm` | recommended; informative only (the speed controller is set by hand), it appears in the header and when generating |
| `profundidad_pasada` | mm per pass; with no value and no job pass = a single pass |
| `feed`, `entrada` | mm/min for cutting and for plunging |
| `stepover` | **% of the diameter** between passes (40, not 0.4); the pocket will use it |

- The file is validated strictly: a misspelled key, a duplicate, an absurd number or a `stepover` as a fraction give an error that names the profile and the field (and suggests the correct key).
- Priority of each value: **job > profile > nothing**: if there is no feed in the job or in the profile, the program stops and says so (it does not cut with an invented value). When generating, it prints where each value comes from.
- Different materials: duplicate the profile with another identifier (`em4_mdf`, `em4_contra`...). The identifier starts with a letter (a number on its own is a diameter).
- For now **only `endmill` tools generate toolpaths**. `ball` and `v` are stored as data; when you try to cut with them the program explains and stops (the effective diameter of a V changes with depth and this still has to be studied).

## Tabs

A tab is a piece of material that the tool does not cut, so that the piece stays attached to the board until you release it by hand. They are marked with the *Tabs* checkbox in the table row (through cuts only, outside or inside: parts and holes, not lines). In the English interface the feature is called "tabs"; the mouse tool is called **Bridge** and its button *Remove bridge*.

- **Master switch**: the *Use tabs* checkbox in the *Tabs* group of the job settings. When off, the G-code comes out without any tabs (neither those of the rows nor those placed by hand, which stay saved and come back when it is switched on again), the *Tabs* checkbox of the rows and the measurements appear grayed out and the Bridge tool warns that they are disabled. It is **remembered on this PC** (so that is how it starts next time) and also travels in the saved job; a job from before the switch leaves it as it was. In `cnc_app.toml` `bridges = false` also works as an initial value, but what was last chosen in the window is remembered and takes precedence over it.
- **Measurements**: the *width* is that of the tab that really remains (6 mm by default); the tool lifts for that width **plus its diameter**, so changing tool does not change the tab. The *height* is the material left above the bottom of the board (2 mm by default): in 19 mm the tool lifts up to Z -17. Only the passes that would go lower than that height rise; the rest of the cut is as usual and without tabs the G-code does not change by a single line.
- **Automatic proposal**: one tab for every 150 mm of perimeter (minimum two), evenly spaced and rotated until they fall on straight sections, away from corners; on a rectangle they end up in the middle of opposite sides. A piece too small to carry them is cut without them and the window says so (a single note per row). The tool never plunges inside a tab: if one falls on the starting point, the path starts where it ends.
- **Where they are seen**: in the *Machine* view, each tab is a thick amber stroke over the toolpath, and the summary says how many there are (*Tabs: 145 on 13 shape(s), 6 mm wide and 2 mm high*).
- **A position is stored as a fraction of the perimeter of the piece**, not as X and Y: moving, rotating or resizing the piece takes its tabs with it.

### Placing and changing tabs by hand

In the *Drawing* view, the tabs appear over the outline of each shape (strong amber those placed by hand, lighter those proposed by the program). The **Bridge** tool (key B, in the *With the mouse:* strip) edits them:

- **Click on an outline** places a tab there (with the width and height from the job settings); if you release after dragging, it stays where you leave it. It also works on **holes**: the tab holds the piece that is cut out. The automatic proposal also puts them on the holes of the rows that ask for them (inside, a very small hole is cut without them).
- **Click on a tab** selects it. **Dragging it** slides it along the outline; **pulling one of its two little squares** changes its width (the other end does not move). **Delete** removes it (it does not delete the shape).
- The tab strip (in the place of the measurements) shows and lets you type its **position** (mm along the outline from its first vertex), its **width** and its **height**; *Remove bridge* and *Shape to automatic* do what they say.
- The first time a shape with automatic tabs is touched, its list switches to **manual**: the ones the program proposed remain as tabs of that shape and count along with the new one. *Shape to automatic* (or *Draw → Tabs of the selection → Automatic*) undoes that; *Remove all* leaves it without any tabs even if the row asks for them.
- Tabs placed by hand **take precedence over the row's checkbox**, are undone and redone like any drawing edit and are saved in the job. They only apply on through-cut rows (on another operation a warning is given and the cut is made without them).

## Default values: `cnc_app.toml`

It is read from the folder you launch the program from and, if it is not there, from the program's folder. (The `herramientas.json` and `maquinas.json` of the packaged program are always read from the program's folder, so that the *Profiles…* and *Machines…* editors always save to the same file.) Each key is the name of a setting with `_` (`safe_z` = safe Z). It has comments with all the possible options. Priority: **what you set in the window > cnc_app.toml > default value**. The one that is delivered enables `rotate = "auto"` and `margin = 0.4`.

## Conventions

mm; Z=0 on the top face of the material; through cuts down to -(thickness + margin);
(0,0) is the lower-left corner of the board (the rectangle with the drawing inside); **without a board, the edge of the material is estimated at the lower-left corner of what is cut and the zero ends up 4 mm outside** (`origin_margin` in `cnc_app.toml`, *Zero at (mm) from drawing* in the window; 0 puts the corner exactly at the zero), so the piece starts 4 mm from both edges and the tool does not go past the zero. With that zero, the *Hold-down* tab assumes an **assumed sheet** that goes from the zero to the maximum coordinate of what is cut plus the same margin (a 540 x 400 mm drawing with margin 4 gives a 548 x 408 mm sheet); it is drawn dashed and changes neither the G-code nor gives warnings that the toolpath goes out of bounds. What the recipe ignores does not count for the corner. It is the same effect as a shift of 4.4, which is added if you set one.
At the end it raises Z, stops the spindle and stays where it ends; with *Return to origin at the end* ticked, it goes back to X0 Y0.
Rotation: the *Rotation* selector rotates N degrees counterclockwise; *Automatic* (what `cnc_app.toml` enables, and the normal choice with boards) rotates 90 degrees only if the toolpath does not fit within the machine travel (651 x 1011) as it is and fits rotated; *Vertical* makes a landscape drawing vertical. The +90 is equivalent to the -90 that would be done by hand to put a landscape drawing on a vertical machine.
Cutting order (the usual one in the shop), checked against six reference G-code files: first the holes, then the parts; each outline starts at the vertex nearest the lower-left corner of its box; holes are traversed starting with the top-left one and always following the nearest, and the parts from top to bottom by their top edge (on a tie, from left to right). The order is fixed: there is no selector.

## Recipes: drills, pockets and cuts in the same drawing

Without a recipe, everything in the drawing is a through cut. With a recipe (the table of operations, which is saved and opened as a `.toml`) the color of each shape decides its operation: the designer marks the operation with the color in the vector drawing application and the recipe, a TOML with comments, says what each color is and with what depth and feeds. `receta_ejemplo.toml` is documented key by key and carries the values of some reference `.nc` files from the 19 mm job.

```toml
ignorar = ["#ffcc00"]                  # guides, dimensions, notes: not cut

[[operacion]]
nombre = "3 mm pockets"
tipo = "vaciado"                       # corte | vaciado | taladro
trazo = "#e63c24"                      # stroke and/or fill color (if both are given, both must be met)
profundidad = 3                        # mm from the top face (or pasante = true)
avance = 1200
entrada = 300
stepover = 60                          # % of the tool diameter between passes
```

- **Order**: operations are cut in the order of the recipe (drills, then pockets, then through cuts in the example; in the window the table is kept in that order and warns if it is not, see *Row order*). Each shape goes to the first operation whose color fits; the colors in `ignorar` take precedence over everything. Shapes that fit nothing are not cut and a warning is given.
- **`corte`**: outline of the piece. `lado = "auto"` decides by nesting (a shape inside another is a hole; outside, a part); also `fuera`, `dentro` or `linea` (the tool goes over the stroke, it accepts open shapes). Without `profundidad` it is a through cut (thickness + margin). Holes first, then parts (the usual order in the shop).
- **`puentes = true`** (only in a through `corte`): leaves **tabs** on the parts and holes that are cut, so they do not move when released from the board. In the window it is the *Tabs* checkbox of the row; the width, the height and the spacing are set in the *Tabs* panel of the settings (`tab_width = 6`, `tab_height = 2` and `tab_spacing = 150` in `cnc_app.toml`, which are the default values).
- **`vaciado`**: removes all the material inside the shape down to `profundidad`. Shapes of the same color that lie inside another are **islands** that are not touched (and if inside an island there is another, it is a pocket again). The rings run parallel to the edge, from the inside outwards, and the last one runs along the wall; a hole that the edge ring already leaves clean (up to about two tool diameters) is made with that ring alone (e.g. the 5 mm holes). With a 4 mm tool, a Ø5 circle is a single 1 mm-diameter loop. The smaller the `stepover`, the more loops: a 682 x 1000 mm pocket with the 3.175 tool at 10 % is about 1,070 loops (≈ 30 h of machine time; at 60 % ≈ 5 h and with a 12 mm one ≈ 47 min), and the "≈ … of machine time" in the summary gives it away before generating. Since 0.23.2 thousands of loops no longer break the calculation (before, "Unexpected application error" appeared beyond ~1000).
- **`taladro`**: one plunge at the center of each circle (`pasada` = peck). It makes a hole of the tool's diameter and warns if the drawn circle has a different diameter; for larger holes use `vaciado`.
- **Priority of each value**: what the operation says > the job's feed and pass > the tool profile. If there is no feed in any of them, the program stops and says in which operation it is missing.
- Colors are written as `"#rrggbb"` (also `#rgb`, `rgb(...)` or a CSS name such as `red`). **A misspelled color is an error**: it is not interpreted as black.
- With boards, the recipe is applied to each one; `receta = "..."` can also go in `cnc_app.toml`.

### Placing the drawing on the board: shift

The *shift* moves the drawing DX,DY mm relative to the zero after placing it (0,7 raises it 7 mm). It is useful when a piece sticks out of the board: if the toolpath goes outside the board, the program warns by how much and on which side, and proposes the shift that fixes it with 4 mm of clearance.

## Boards (several materials in one SVG)

Convention: a **rectangle with shapes inside** is a board = a job = a `.nc`. The rectangle is not cut and the zero is at its lower-left corner. An **ellipse or circle that contains boards** is only a visual grouping and is discarded. A shape belongs to the board if at least half of it falls inside (a piece that sticks out a little is still its own; see *Placing the drawing on the board*). Whatever is left outside every board is not cut (a warning is given). A rectangle inside a board is an ordinary piece.
Boards are numbered from left to right by columns and from top to bottom within each column; the boards table shows them with their size and how many parts and holes they have, and the ones to generate are ticked (all by default); with several, the output is `NAME_board1.nc`, `NAME_board2.nc`...
Limits: a rectangle with holes inside (a rectangular plate with holes) is indistinguishable from a board with parts; this is solved by unticking *Detect boards*. The tool and the feeds are the same for all the boards of a job; what can change per board is the thickness, the margin, the rotation and the shift.

Usage errors come out on one line (`ERROR: ...`, exit code 2) and generation errors too (code 1); never a traceback.
